# CS Daily Drill

개인용 CS 학습 웹앱. **Phase 3** 까지 되어 있다 — 간격 반복 복습, 아침 뉴스 브리핑,
모의 시험, 학습 통계, 문항 관리까지 갖췄다.

## 실행

Node 22 가 필요하다. 시스템 기본이 Node 20 이면 먼저 `nvm use`.

```bash
npm install && npm run dev
```

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run validate` | 문제은행 전체 검증 + 주제별 분포 출력 |
| `npm run build` | 프로덕션 빌드 (앞에 `validate` 가 자동으로 붙는다) |
| `npm run ingest` | 뉴스 수집 → `content/news/YYYY-MM-DD.json` |
| `npm test` | `src/lib` 로직 테스트 147개 |
| `npm run lint` | ESLint |

## 화면

| 경로 | 상태 |
|---|---|
| `/` | 오늘 날짜 · 연속 학습일 · 남은 카드 진행 링 · 복습/신규 내역 · 드릴 시작 |
| `/drill` | 카드 넘기며 채점. 데스크톱은 2단(왼쪽 질문+메모 / 오른쪽 모범답안) |
| `/manage` | 전체 문제 목록 · 주제 필터 · 검색 · 펼쳐서 답 보기 |
| `/briefing` | 오늘자 카드 · 태그 필터 · 북마크 · 지난 날짜 무한 스크롤 |
| `/manage/new` | 브리핑에서 넘어온 문제 초안. JSON 을 만들어 준다 |

| `/stats` | 1년 잔디 히트맵 · 스트릭 · 주제별 정답률 · 오답노트 · 성숙도 · 잔량 |

## 왜 이렇게 만들었는지

- **`src/lib/srs.ts` 는 순수 함수다.** React·Dexie·`Date.now()` 를 쓰지 않고 오늘 날짜를 인자로 받는다.
  그래서 `srs.test.ts` 의 D0~D201 시퀀스를 한 줄씩 고정할 수 있다. 간격 계산은 이 앱의 심장이라
  회귀가 나면 조용히 몇 달치 복습 일정이 틀어진다.
- **`schedule()` 은 ease 를 먼저 조정하고 reps 를 올린다.** 순서가 바뀌면 Easy 를 누른 그 회차의
  간격이 달라진다. 테스트가 이 순서를 잡아 둔다.
- **하루 상한에서 '오늘 이미 한 몫'을 뺀다.** 평가를 마친 카드는 상태가 생겨 '신규'에서 빠지므로,
  그것만으로 큐를 짜면 하루에 몇 번이든 새 카드를 꺼낼 수 있다. 그만큼 내일 복습 빚이 늘어난다.
  복습과 신규는 **같은 총량(60)** 을 나눠 쓰고, 세는 단위는 채점 횟수가 아니라 카드 장수다.
- **되돌리기는 역산이 아니라 스냅샷 복원이다.** `reviewLogs.prev` 에 평가 직전 상태를 통째로 넣어
  둔다. Again 은 정보를 잃어서 역산이 불가능하다.
- **날짜는 전부 `'YYYY-MM-DD'` 문자열이다.** `Date` 뺄셈은 DST 가 있는 지역에서 하루씩 밀린다.
  오늘 날짜는 서버가 `todayStr('Asia/Seoul')` 로 정해 내려보낸다 — 배포 환경이 UTC 라도 하루가 안 어긋난다.
- **문제은행은 Git 이 관리하는 정적 JSON, 학습 이력은 IndexedDB.** 문제를 고치는 일과 기록을 쌓는
  일은 수명이 다르다. 섞으면 문제 하나 고칠 때마다 이력 마이그레이션을 하게 된다.

## 뉴스 수집

```bash
npm run ingest
```

GeekNews(Atom) · Hacker News(Algolia, 150점 이상) · arXiv(cs.AI/cs.LG/cs.CL)에서 모아
중복을 걸러내고 하루 8건까지 고른 뒤, 요약해서 `content/news/YYYY-MM-DD.json` 에 쓴다.

요약에는 OpenAI API 키가 필요하다. `.env` 의 `OPENAI_API_KEY=` 뒤에 키를 붙여 넣는다.
**키가 없어도 정상 종료한다** — 요약만 비우고 제목·링크는 저장한다.

`.github/workflows/ingest.yml` 이 매일 06:30 KST 에 같은 일을 하고 `content/news/` 에
변경이 있을 때만 커밋한다. 저장소 시크릿 `OPENAI_API_KEY` 가 필요하다.

## 시험과 복습의 관계

`/exam` 은 드릴과 따로 돈다. 다만 **틀린 문항만** 복습 일정에 되먹인다 —
`due` 를 오늘로 당기고 `ease` 를 0.15 깎는다. 그래서 다음 드릴에서 큐 앞쪽에 온다.
자가 채점의 '애매' 는 점수 0.5점으로만 세고 일정은 건드리지 않는다.

## 문항 고치기

`/manage` 에서 문항을 추가·수정하면 **브라우저(IndexedDB)에만** 저장된다.
화면은 Git 문제은행 위에 이 수정을 얹어 보여준다(같은 id 는 수정본 우선).

레포에 남기려면:

1. `/manage` → `JSON 내보내기` → 주제별로 복사
2. `content/questions/<주제>.json` 에 붙여넣기
3. `npm run validate` 통과 확인 후 커밋

이 과정을 거치지 않으면 브라우저 데이터를 지울 때 함께 사라진다.

## 문제 추가하기

`content/questions/<주제>.json` 에 항목을 넣고 `npm run validate` 를 돌린다.

```json
{
  "id": "os-process-001",
  "topic": "os",
  "subtopic": "process",
  "difficulty": 1,
  "type": "concept",
  "question": "프로세스와 스레드의 차이는?",
  "answerShort": "30초 안에 말할 수 있는 답",
  "answerDeep": "꼬리 질문까지 대비한 설명 (선택)",
  "keywords": ["프로세스", "스레드"],
  "source": "seed"
}
```

`type` 이 `mcq` 나 `ox` 면 `choices` 와 `correct`(0-based 인덱스)가 필수다.
`topic` 은 network · os · db · ds · algo · lang · web · arch · devops · ai 중 하나이고,
id는 반드시 그 topic 으로 시작해야 한다. **한 번 발급한 id 는 바꾸지 않는다** — 바꾸면
그 카드의 복습 이력이 끊긴다.

## 안 되는 것 · 한계

- **문제은행이 os 22문항뿐이다.** 나머지 9개 주제는 비어 있다.
- **요약은 발췌가 있어야 만들어진다.** 피드가 발췌를 안 주면 원문에서 한 번 가져오는데,
  봇 차단·타임아웃으로 실패하면 그 기사는 요약 없이 남는다(제목만으로 억지 요약을 만들지 않는다).
- **`/manage/new` 는 저장하지 않는다.** 브라우저가 `content/questions/*.json` 에 쓸 수 없어서,
  붙여넣을 JSON 을 만들어 주는 데까지만 한다.
- **북마크한 기사를 모아 보는 화면이 없다.** 저장은 되지만 목록이 없다.
- **요약 품질은 발췌에 좌우된다.** 피드 설명이 짧으면 요약도 얕아진다.
- **원문을 한 번 긁는다.** 피드에 발췌가 없을 때만, 8초 타임아웃으로. 가져온 본문은 저장하지 않는다.
- **학습 기록이 이 브라우저에만 있다.** 서버로 동기화하지 않는다. 브라우저 데이터를 지우거나
  기기를 바꾸면 이력이 사라지고, 내보내기·가져오기 기능도 아직 없다.
- **되돌리기는 한 단계씩만 거슬러 올라간다.** 세션을 벗어나면(새로고침) 그 세션의 되돌리기 이력이 사라진다.
  단 DB 의 `reviewLogs` 는 남아 있어 마지막 평가 하나는 여전히 되돌릴 수 있다.
- **문항 수정이 레포에 자동 반영되지 않는다.** 내보내기 → 붙여넣기 → 커밋을 사람이 해야 한다.
- **`/manage/new` 는 오버레이에 저장하지 않는다.** 브리핑에서 넘어온 초안은 JSON 을 만들어 줄 뿐이다
  (`/manage` 의 `새 문항` 은 오버레이에 저장된다).
- **시험 기록을 되돌아보는 화면이 없다.** `examResults` 에 쌓이지만 목록 UI 가 없다.
- **키워드 체크박스와 메모는 저장하지 않는다.** 카드를 넘기면 사라진다(의도된 동작).
- **통계·시험·브리핑이 없다.** 정답률은 드릴 완료 화면에서 그 세션 몫만 보여준다.
- 문제은행을 서버에서 매 요청 읽는다. 문항이 수천 개가 되면 첫 렌더가 느려진다.
